# deid — 진료 기록 개인정보 지우개

진료 메모, 엑셀, PDF, 워드, 한글(HWPX), 화면 캡처, 클립보드에서 **환자·보호자·직원의 개인정보를 찾아
가리는 도구**입니다. ChatGPT나 Claude 같은 클라우드 AI에 붙여넣기 전, 또는 동료·학회와 자료를 나누기 전에
씁니다. 기본으로 모든 처리는 이 Mac 안에서만 합니다. (진료실 PC의 LLM 서버를 탐지에 연결하면 그 PC까지 갑니다 —
[진료실 LLM 서버 연결](#strata-등-진료실-llm-서버-연결))

> **먼저 꼭 읽어 주세요**
>
> - deid는 개인정보가 새어 나갈 **위험을 줄여 줄 뿐, 없애 주지는 못합니다.**
> - 자동 탐지는 놓치는 것이 있습니다. 특히 `님`·`환자` 같은 말 없이 이름만 쓴 경우, 손글씨, 사진 속
>   얼굴은 놓치기 쉽습니다 ([한계와 주의](#9-한계와-주의)).
> - 그래서 결과는 **공유하거나 붙여넣기 전에 반드시 직접 읽어 보세요.** 도구가 "완료"라고 해도 마지막
>   확인은 사람이 합니다.

## 1. 무엇을 하는 도구인가

- **기본은 100% 로컬**: 기본 설정에서는 모든 처리를 이 Mac 안에서만 합니다. 인터넷으로 아무것도 보내지
  않습니다. (예외는 여러분이 직접 하는 것뿐입니다: 처음 한 번 프로그램·모델을 내려받을 때. 선택 기능인
  로컬 LLM(Ollama)은 이 Mac 안의 주소(127.0.0.1)로만 연결합니다.)
- **진료실 LLM 서버를 연결하면 그 PC까지**: 설정에서 진료실 PC의 LLM 서버(Strata 등)를 *탐지*에 연결하면
  비식별화 **전** 원문이 병원 내부망으로 그 PC까지 갑니다. 기본은 꺼져 있고, 켜 두면 명령마다 경고가 나옵니다
  ([진료실 LLM 서버 연결](#strata-등-진료실-llm-서버-연결)).
- **한국어 우선**: 주민등록번호, 휴대폰·유선 번호, 도로명/지번 주소, `김민준 님`·`보호자 이서연`·
  `환자명: 박서윤` 같은 이름, 차트번호(등록번호) 등을 찾습니다. 영어 이름·주소·전화번호도 찾습니다.
- **원본은 바꾸지 않습니다.** 결과는 새 파일(`이름.deid.확장자`)이나 클립보드로 나옵니다.
- **가명은 일관되게**: 같은 사람은 문서 전체에서 같은 `[이름1]`이 됩니다. LLM 답변을 받은 뒤
  `[이름1]`을 원래 이름으로 **이 Mac 안에서** 되돌릴 수 있습니다(`deid restore`).
- 결과 요약에는 **개수만** 나옵니다 (`이름 2, 전화번호 1`). 찾은 값 자체는 화면·로그에 남기지 않습니다.

### 무엇을 어떻게 가리나 (기본값)

처리 방법: **가명**(pseudo) = 같은 값은 같은 표시로, 나중에 복원 가능 · **일부 가림**(mask) ·
**통째로 가림**(redact) · **넓게 바꿈**(generalize) · **그대로 둠**(keep, 개수만 셈)

| 항목 | 예 | 기본 처리 | 결과 예 |
| --- | --- | --- | --- |
| 이름 (PERSON) | 김하늘 님, 보호자 도윤재, Dr. James Carter | 가명 | `[이름1]` |
| 주민등록번호 (RRN) | 900101-2345678 | 통째로 | `[주민번호]` |
| 외국인등록번호 (FRN) | 900101-5345678 | 통째로 | `[외국인번호]` |
| 전화번호 (PHONE) | 010-2345-6789, 02-512-3344, +82 10 … | 일부 가림 | `010-****-6789` |
| 이메일 (EMAIL) | haneul.kim@example.com | 가명 | `[이메일1]` |
| 주소 (ADDRESS) | 서울특별시 강남구 테헤란로 123, 101동 1203호 | 넓게 | `서울특별시 강남구 [주소]` |
| 주소 (제목이 붙은 짧은 주소) | `주소: 정자동 행복아파트 102-1501`, `우편번호 13561` | 넓게 | `주소: [주소]` |
| 생년월일 (BIRTHDATE) | 생년월일 1990.01.01, 85년생, `표다은(79.04.05, F)`, 1979년 4월 5일 출생 | 넓게 | `1990년생` |
| 날짜 (DATE) | 진료일 2025-03-02 | **그대로** | `2025-03-02` |
| 등록번호·차트번호 (MRN) | 등록번호: 12345678 (앞에 '등록번호', '차트번호', 'MRN' 같은 말이 있을 때) | 가명 | `[등록번호1]` |
| 카드번호 (CARD) | 4111-1111-1111-1111 | 통째로 | `[카드번호]` |
| 계좌번호 (ACCOUNT) | 국민은행 계좌 123456-01-234567 (은행·계좌 같은 말이 있을 때) | 통째로 | `[계좌번호]` |
| 여권·운전면허·사업자등록·건강보험증 번호 | M12345678, 11-23-456789-01 … | 통째로 | `[여권번호]` 등 |
| 보건의료인 면허번호 | 의사면허번호 제12345호 | 통째로 | `[면허번호]` |
| 차량번호 (PLATE), IP 주소 | 12가3456, 192.168.0.12 | 통째로 | `[차량번호]`, `[IP]` |
| 기타 식별번호 (OTHER) | 보험 청구번호, 사번 등 | 통째로 | `[기타]` |
| 웹 주소 (URL) | `https://emr.example/p?name=표다은` | 주소는 **그대로**, 그 안의 개인정보만 가림 | `https://emr.example/p?name=[이름1]` |
| 기관 이름 (ORG) | 하늘내과, ○○약국, △△초등학교 (LLM 탐지를 켰을 때만 찾음, 예: 진료실 LLM 서버) | **그대로** (개수만) | `하늘내과` |

날짜를 가리거나, 웹 주소를 통째로 지우거나, 전화번호를 통째로 가리거나, 기관 이름을 가리고 싶으면

### 지원 형식

| 종류 | 확장자 | 가리는 곳 | 통째로 지우는 것 (경고로 알림) |
| --- | --- | --- | --- |
| 텍스트 | txt md log srt vtt json jsonl html xml | 본문. 엑셀에서 복사해 붙인 표(탭으로 나뉜 글)는 열 제목으로 판단 | — |
| 엑셀 | xlsx xlsm csv tsv | 모든 시트의 셀, 메모, 시트 이름, 머리글/바닥글, 수식 속 글자, 차트 제목. `이름`·`연락처`·`주민번호` 같은 **열 제목**으로 그 열 전체를 판단 | 그림, 도형·텍스트 상자, 피벗 테이블(원본 데이터 사본이 들어 있음), 다른 통합문서 연결, 메일·전화 링크. 문서 정보(만든 사람 등)는 비움 |
| 워드 | docx docm dotx dotm | 본문, 표, 머리글/바닥글, 각주, 메모, 변경 내용, 그림(글자 인식) | 변경 내용 추적에 남은 삭제된 글자, 포함된 개체(엑셀 표·OLE)의 내용, 미리보기 그림. 문서 정보는 비움 |
| 한글 | hwpx | 본문, 표, 메모, 누름틀, 그림(글자 인식) | 포함된 개체(OLE)의 내용, 미리보기 그림. 문서 정보는 비움 |
| PDF | pdf | 글자를 **실제로 지움**(덮기만 하지 않음). 스캔 쪽은 글자 인식 후 검은 상자 | 첨부 파일, 전자서명, 숨은·인쇄 전용 주석, XFA 양식 데이터, 메일·전화 링크, 문서 정보 |
| 이미지 | png jpg jpeg webp bmp tif tiff heic heif | 글자 인식(OCR) 후 검은 상자 | 사진 정보(EXIF, GPS) |

xlsm·docm 안의 **매크로(VBA)는 검사하지 않고 그대로 남깁니다**(경고 표시). 공유용이면 매크로 없는
형식(xlsx, docx)으로 저장하세요.

**지원하지 않는 형식**

| 파일 | 이렇게 하세요 |
| --- | --- |
| xls, doc, hwp (예전 형식) | 엑셀·워드·한글에서 **다른 이름으로 저장** → xlsx / docx / hwpx |
| pptx, ppt, key (발표 자료) | **PDF로 내보내기** 한 뒤 처리 |
| pages, numbers, odt, ods, rtf | docx / xlsx로 저장(내보내기)한 뒤 처리 (pages는 PDF도 됨) |
| dcm (DICOM 영상) | 처리하지 못합니다. PACS의 **익명화 내보내기** 기능을 쓰거나, 화면에 띄워 `deid shot`으로 캡처 (캡처 이미지에는 DICOM 안의 숨은 정보가 따라가지 않음) |
| gif | png로 바꾼 뒤 처리 |
| zip | 압축을 풀고 그 폴더를 지정 |
| eml(메일), 동영상, 음성 | 처리하지 못합니다 |

파일을 하나씩 지정하면 이유와 바꾸는 방법을 알려 줍니다. 하지만 **폴더**를 처리할 때 dcm·gif·eml·동영상
같은 파일은 마지막에 `건너뜀 (skipped)`으로 **개수만** 나오고, 자동 감시 폴더(`~/Deid/in`)에서는 아무
표시 없이 그대로 남습니다(결과가 생기지 않음). 이런 파일이 원본 그대로 공유되지 않도록 주의하세요.

## 2. 설치 · 업데이트 · 지우기 (M1 맥 기준)

"터미널" 앱을 엽니다 (⌘+스페이스 → "터미널"). 아래 상자의 줄을 **한 줄씩** 붙여넣고 Enter를 누릅니다.

**① Homebrew** (맥용 프로그램 설치 도구) — 이미 있다면 건너뜁니다. `brew --version`이 숫자를 보여 주면 있는
것입니다.

```sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치가 끝나면 화면 마지막의 "Next steps" 두 줄을 그대로 실행합니다. M1 맥에서는 보통 다음과 같습니다.

```sh
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

**② 파이썬, 글자 인식(OCR), pipx 설치**

```sh
brew install python@3.12 tesseract tesseract-lang pipx
pipx ensurepath
```

터미널 창을 **닫았다가 다시 엽니다.**

**③ deid 설치** — 둘 중 하나

- 인터넷 저장소에서 바로:

  ```sh
  pipx install --python python3.12 "git+https://github.com/softkorea/softkorea.github.io.git@claude/deid-toolkit#subdirectory=tools/deid"
  ```

  (정식으로 합쳐진 뒤에는 `@claude/deid-toolkit` 부분을 빼고 실행합니다.)

- 이 폴더를 이미 내려받았다면 (위치는 실제 경로로 바꾸세요):

  ```sh
  pipx install --python python3.12 ~/softkorea.github.io/tools/deid
  ```

`uv`를 쓰는 분은 `brew install uv` 후 `uv tool install --python 3.12 "git+https://github.com/softkorea/softkorea.github.io.git@claude/deid-toolkit#subdirectory=tools/deid"`
로도 설치할 수 있습니다. (이 경우 아래의 `pipx inject …` 대신 `uv tool install --with 패키지이름 …`으로
다시 설치합니다.)

**④ 점검**

```sh
deid doctor
deid --version
```

`[OK]`는 정상, `[--]`는 선택 기능(없어도 됨), `[!!]`는 확인 필요, `[XX]`는 꼭 고쳐야 하는 항목입니다.
`[!!]`/`[XX]` 아래의 `->` 줄이 고치는 방법입니다. 맥에서는 Apple의 글자 인식(Vision/Live Text)도 함께
설치되며, 한국어는 macOS 13 이상에서 인식됩니다. `deid --version`은 버전 번호와 어디서 설치했는지를
보여 줍니다 (인터넷 저장소에서 설치했다면 `deid 0.2.0 (git 1a2b3c4, …)`처럼 커밋 번호도, 폴더로 설치했다면
설치한 시각도). 문제를 물어볼 때 함께 알려 주세요.

### 업데이트

```sh
pipx install --force "git+https://github.com/softkorea/softkorea.github.io.git#subdirectory=tools/deid"
```

- **아직 정식으로 합쳐지기 전**(설치할 때 주소에 `@claude/deid-toolkit`이 있었다면)에는 그 부분을 넣습니다.

  ```sh
  pipx install --force "git+https://github.com/softkorea/softkorea.github.io.git@claude/deid-toolkit#subdirectory=tools/deid"
  ```

- 폴더로 설치했다면 먼저 그 폴더를 최신으로 바꾼 뒤(`git -C ~/softkorea.github.io pull`) 같은 방법으로:
  `pipx install --force ~/softkorea.github.io/tools/deid`
- `uv`로 설치했다면: `uv tool install --reinstall "git+…(위와 같은 주소)"`
- `pipx reinstall`은 처음 설치한 주소를 그대로 다시 쓰기 때문에, 주소가 바뀌면 실패할 수 있습니다.
  위의 `pipx install --force`를 쓰세요. (`pipx inject`로 넣은 추가 기능은 그대로 남습니다.)

**업데이트한 뒤에 할 일**

1. `deid --version` — 버전 번호나 `git …` 커밋 번호가 바뀌었는지 확인합니다. 폴더로 설치했다면 커밋 번호 대신
   끝에 나오는 `설치 2026-…` 시각이 방금으로 바뀌었는지 봅니다.
2. 자동 감시를 켜 두었다면 `deid install-watch`를 **한 번 더** 실행합니다. 처음 설치할 때 `--in`, `--out`,
   `--no-notify`를 붙였다면 똑같이 붙입니다. 켜져 있던 감시는 다시 시작하기 전까지 예전 프로그램으로 돕니다.
3. `deid serve`를 켜 두었다면 Ctrl-C로 끄고 다시 `deid serve`.
4. `deid doctor`로 점검.

### 지우기 (순서대로)

1. 자동 감시를 켰다면 **먼저** 끕니다. 켜 둔 채 프로그램부터 지우면 macOS가 없는 프로그램을 30초마다 다시
   실행하려고 합니다.

   ```sh
   deid install-watch --uninstall
   ```

2. 가명 대응표(세션 보관함)와 키체인 열쇠를 지웁니다. 무엇을 지웠는지 보여 줍니다.

   ```sh
   deid forget
   ```

3. 프로그램을 지웁니다: `pipx uninstall deid-kit` (uv로 설치했다면 `uv tool uninstall deid-kit`)
4. 남은 설정·기록·작업 폴더를 지웁니다 (필요하면). **`~/Deid/in`에 원본이 남아 있을 수 있으니 먼저
   Finder에서 열어 확인**하세요.

   ```sh
   rm -rf ~/.config/deid "$HOME/Library/Application Support/deid" ~/Library/Logs/deid-watch.log ~/Deid
   ```

5. 원본 옆에 생긴 `deid_out` 폴더, `--vault`로 만든 보관함 파일, 그리고 (만들었다면) 키체인의
   `deid-vault` 항목은 직접 지웁니다 (`security delete-generic-password -a "$USER" -s deid-vault`).

## 3. 가장 쉬운 사용법 3가지

### ① 브라우저 화면 — `deid serve`

```sh
deid serve
```

브라우저가 열립니다. 글을 붙여넣고 **비식별화** → **복사**. LLM 답변을 붙여넣고 **원래대로 복원**.
파일을 창에 끌어다 놓으면 처리된 파일이 바로 다운로드됩니다 (50MB까지).

- 이 Mac(127.0.0.1)에서만 열리고, 주소 끝의 비밀 토큰(`?t=…`)이 없으면 접속되지 않습니다.
- 탐지에 진료실 LLM 서버를 연결해 두었다면 화면 맨 위에 "원문이 그 서버로 전송됩니다"라는 경고가 나옵니다.
- 끝내려면 터미널에서 **Ctrl-C** (터미널 창을 닫아도 됩니다. 처리 중이던 임시 파일은 지워집니다).
- 다른 포트: `deid serve --port 8800`, 브라우저 자동 열기 끄기: `deid serve --no-browser`
- 켜 둔 채 설정 파일을 고치면 다음 요청부터 새 설정을 씁니다. 고친 설정에 오류가 있으면 이전 설정으로
  계속 처리하고 화면에 경고를 보여 줍니다.

### ② 클립보드 — `deid clip` / `deid restore` (ChatGPT·Claude와 주고받기)

1. 전자의무기록(EMR)에서 글을 선택해 **⌘C**
2. 터미널에서 `deid clip` (또는 [단축키](#6-단축키--finder-빠른-동작-연결)) → 클립보드의 글이 가린 글로 바뀝니다.

   ```text
   환자: 박서윤 (F/62)  등록번호 00482917          →   환자: [이름1] (F/62)  등록번호 [등록번호1]
   딸(한지민, 010-4471-2290)과 함께 내원.          →   딸([이름2], 010-****-2290)과 함께 내원.
   ```

3. ChatGPT/Claude 입력창에 **⌘V**. 붙여넣기 전에 한 번 읽어 보세요.
   *팁*: 질문에 "`[이름1]` 같은 표시는 바꾸지 말고 그대로 써 주세요"라고 덧붙이면 복원이 잘 됩니다.
4. 답변을 복사(**⌘C**) → `deid restore` → `[이름1]`이 원래 이름으로 바뀐 답변이 클립보드에 들어갑니다.
   조사도 원래 이름에 맞게 고칩니다 (`[이름2]와` → `한지민과`).

- 클립보드에 **이미지**(캡처)가 있으면 글자를 읽어 개인정보 부분을 검은 상자로 가린 이미지로 바꿉니다.
- 처리에 실패하면 실수로 원문을 붙여넣지 않도록 **클립보드를 비우고** 알려 줍니다.
- 답변 속 **링크(URL) 안의 가명은 복원하지 않습니다.** (예: `![](https://…?p=[이름1])` 같은 링크가 답변에
  섞여 있으면, 복원한 글을 붙여넣는 순간 이름이 다른 서버로 전송될 수 있기 때문입니다.)
- 맥이 아닌 곳에서는 `deid text < 원본.txt > 결과.txt`, 복원은 `deid text --restore < 답변.txt`.

**대응표(세션 보관함)는 언제 지워지나**

- `[이름1]` ↔ 원래 이름 대응표는 암호화되어 이 Mac에 저장되고(열쇠는 macOS 키체인), **마지막으로 쓴 뒤
  12시간** 동안 쓰지 않으면 열쇠와 함께 지워집니다. 지우는 때는 *다음에 deid를 실행할 때*이고, 자동 감시나
  `deid serve`가 켜져 있으면 곧바로입니다. 그 전까지는 이 Mac에 (암호화된 채) 남아 있습니다.
- 그 안에서는 한 번 가린 이름이 다음 글에서 문맥 없이 나와도 다시 가립니다.
- **자리를 비우거나 Mac을 다른 사람에게 넘기기 전에는** `deid forget`. 무엇을 지웠는지 보여 줍니다.
- 만료되거나 `deid forget`을 한 뒤에는 가명이 다시 `[이름1]`부터 시작합니다. 같은 LLM 대화창에서 이어
  쓰면 예전 `[이름1]`과 새 `[이름1]`(다른 사람)이 섞이니, **새 환자는 새 대화창에서** 시작하세요.
- 보관함이 언제 시작됐고 마지막으로 언제 썼는지, 지워지기까지 얼마나 남았는지는 `deid doctor`의
  "세션 보관함" 줄에 나옵니다.

### ③ 파일 — `deid file`

```sh
deid file 진료기록.docx 검사결과.xlsx
```

원본 옆 **`deid_out`** 폴더에 `진료기록.deid.docx`처럼 저장됩니다. 원본은 그대로입니다.

| 하고 싶은 일 | 명령 |
| --- | --- |
| 폴더 안 파일 모두 | `deid file ~/Desktop/자료` |
| 결과를 다른 폴더에 | `deid file ~/Desktop/자료 -o ~/Desktop/공유용` |
| 저장하지 않고 개수만 보기 | `deid file 자료 --dry-run` |
| 여러 번 나눠 실행해도 같은 사람은 같은 가명 | `deid file 자료 --vault ~/deid.vault` (암호를 물어봄) |
| 나중에 `deid restore`로 복원 | `deid file 메모.txt --session` |
| 제목만으로 알 수 없는 엑셀 열 지정 | `deid file 명단.xlsx --column "담당=PERSON" --column "약품명=skip"` |
| 끝나면 알림 (개수만) | `deid file 자료 --notify` |
| 결과 요약을 JSON으로 (다른 프로그램·스크립트용. 원본 파일 경로가 그대로 들어가니 파일로 남겨 두지 마세요) | `deid file 자료 --report json` |

- 파일 이름에 환자 이름이 있으면 결과 파일 이름도 `[이름1]_외래기록.deid.docx`처럼 바뀝니다.
- 처리 중 경고(예: "문서 안 이미지 2개는 검사하지 않음", "그림 1개를 제거했습니다")가 나오면 그 부분은
  직접 확인하세요.
- `--vault`도 `--session`도 붙이지 않으면 대응표를 남기지 않으므로, 그 결과의 `[이름1]`은 복원할 수 없습니다.

**보관함 파일(`--vault`)로 만든 결과 복원하기**

| 하고 싶은 일 | 명령 |
| --- | --- |
| 클립보드의 LLM 답변 복원 | `deid restore --vault ~/deid.vault` |
| 파일로 저장한 답변 복원 | `deid text --restore --vault ~/deid.vault < 답변.txt > 복원.txt` |

- 둘 다 보관함 암호를 묻습니다. 만들 때와 **같은 파일, 같은 암호**를 써야 합니다.
- **암호를 잊으면 복원할 수 없습니다.** 되살릴 방법이 없으니 암호는 안전한 곳(예: 키체인)에 따로 보관하세요.
- `--vault` 없이 `deid restore`를 하면 세션 보관함만 보므로 이 가명들은 복원되지 않습니다.
- 빠른 동작·단축어처럼 암호를 입력할 창이 없는 곳에서는 `DEID_VAULT_PASS` 환경변수로 암호를 넘겨야 합니다
  (없으면 오류로 멈춤). 스크립트에 암호를 그대로 적지 말고 키체인에서 꺼내 쓰는 방법을
  [macos/README.md](macos/README.md)의 5번 "보관함 파일(`--vault`)을 빠른 동작·단축어에서 쓰기"에 적어
  두었습니다.

## 5. 폴더 자동 처리: watch

**로그인할 때마다 자동으로** (권장):

```sh
deid install-watch
```

이제 `~/Deid/in` 폴더에 파일을 넣으면 몇 초 뒤 `~/Deid/out`에 결과가 생깁니다.

- 원본은 옮기거나 지우지 않습니다. 다 쓴 원본은 직접 지우세요.
- 같은 파일을 고쳐 다시 저장하면 다시 처리합니다.
- 알림에는 파일 종류와 개수만 나옵니다. 알림 끄기: `deid install-watch --no-notify`
- 다른 폴더: `deid install-watch --in ~/Deid/받은파일 --out ~/Deid/보낼파일`
- 기록: `~/Library/Logs/deid-watch.log` (원본 파일 이름은 남기지 않습니다)
- 제거: `deid install-watch --uninstall` · 설정 내용만 보기: `deid install-watch --print`
- **설정 파일을 고치면** 켜 둔 감시도 다음 파일부터 새 설정을 씁니다. 고친 설정에 오류가 있으면 이전 설정으로
  계속 처리하고 기록 파일에 경고를 남기며 (알림을 켰다면) 알림으로도 알려 주니, 고친 뒤에는 `deid doctor`로
  확인하세요. 설정 파일에 오류가 있는 동안은 `deid install-watch`가 설치하지 않고 이유를 알려 줍니다.
- **deid를 업데이트한 뒤에는** `deid install-watch`를 한 번 더 실행하세요 (처음과 같은 옵션으로).
- 지원하지 않는 파일(dcm, gif, eml …)은 아무 표시 없이 `in`에 남습니다.
- 자동 감시 결과의 `[이름1]`은 대응표를 저장하지 않으므로 복원할 수 없습니다.
- 감시 폴더를 **바탕화면·문서·다운로드** 안에 두지 마세요 (macOS 보호 폴더라 백그라운드 작업이 멈출 수 있음).
- `~/Deid` 폴더들은 이 계정만 열 수 있게(권한 700) 만듭니다.
- 폴더 안의 **바로가기(심볼릭 링크)는 처리하지 않습니다** (다른 곳의 파일이 딸려 나가지 않도록).
- 탐지에 진료실 LLM 서버를 연결했다면: 시작할 때 기록에 원문 전송 경고를 남깁니다. 서버가 꺼져 있거나 키가
  틀려 처리하지 못한 파일은 결과를 만들지 않고 기록에 `FAIL`로 남으니, 서버를 고친 뒤 그 파일을 다시
  저장하거나 다시 넣으세요. 자동 감시(로그인 시 시작)는 터미널의 환경변수를 모르니 API 키는 **키체인**에 넣으세요
  (`deid key set`).

터미널을 켜 둔 동안만 잠깐 감시하려면: `deid watch ~/Deid/in ~/Deid/out` (Ctrl-C로 종료, 확인 간격
`--interval 5`, 알림 `--notify`).

## 7. 설정 파일

```sh
deid init-config                      # ~/.config/deid/config.toml 예시 파일 만들기
open -e ~/.config/deid/config.toml    # 텍스트 편집기로 열기
deid doctor                           # 고친 뒤 제대로 읽히는지 확인
```

- 형식은 TOML입니다. `#` 뒤는 설명(주석)입니다.
- `names`, `allowlist`, `min_score`, `disabled`는 **파일 맨 위**(`[actions]` 같은 제목보다 앞)에 둡니다.
- **init-config로 만든 파일에서는** 맨 위에 이미 있는 `names = [ … ]` 목록 **안에** 이름을 넣으세요.
  파일 끝에 `names = [...]` 줄을 새로 붙이면 마지막 `[제목]` 아래로 들어가 버립니다(`deid doctor`가 `[!!]`로
  알려 줍니다).

  ```toml
  names = [
    "강지윤",
    "백승호",
  ]
  ```

- 아래 **의원용 예시를 쓰려면 파일 내용을 모두 지운 뒤 붙여넣으세요.** `[actions]` 같은 제목이 한 파일에
  두 번 있으면 오류가 납니다.
- 정규식(regex)은 **작은따옴표** `'...'`로 감싸면 `\d`, `\s`를 그대로 쓸 수 있습니다.
- 항목 이름은 대소문자를 가리지 않습니다 (`phone` = `PHONE`).
- **설정에 오타나 모르는 이름이 있으면 deid는 처리하지 않고 멈춥니다**(무시하고 넘어가지 않음). 무엇이
  틀렸는지와 비슷한 이름("'actions'을(를) 말씀하신 건가요?")을 알려 줍니다. `deid doctor`에서는 꼭 고쳐야 할
  오류는 `[XX]`, 적용은 되지만 고쳐야 할 점은 `[!!]`로 나옵니다.
- 고친 설정은 다음 명령부터 바로 쓰입니다. 켜 둔 자동 감시와 `deid serve`도 다음 파일·요청부터 새 설정을
  씁니다(오류가 있으면 이전 설정 유지 + 경고).
- 다른 설정 파일 쓰기: `deid file … --config 경로` 또는 환경변수 `DEID_CONFIG`.

### 의원용 예시

```toml
# 항상 이름으로 가릴 사람 (직원, 자주 나오는 환자). 문맥이 없어도 찾습니다.
names = ["강지윤", "백승호", "서다인"]

# 이름처럼 보여도 그대로 둘 낱말 (병원·약국 이름 등)
allowlist = ["하늘내과", "푸른약국"]

# 탐지 점수 하한 (0.0~1.0, 낮출수록 더 많이 가림)
# min_score = 0.5

# 아예 찾지 않을 항목
# disabled = ["URL"]

# 항목별 처리: pseudo(가명) | mask(일부) | redact(통째로) | generalize(넓게) | keep(그대로)
[actions]
PHONE = "redact"          # 전화번호를 [전화번호]로 통째로
DATE = "generalize"       # 진료일도 '2025년 3월'로 넓게
# URL = "redact"          # 웹 주소를 [URL]로 통째로 (EMR 링크를 자주 붙여넣는다면)
CHART = "pseudo"          # 아래에서 만든 항목: [차트번호1], [차트번호2] ...

# 결과에 보일 표시 이름
[labels]
CHART = "차트번호"
STAFF_ID = "사번"

# 우리 의원 차트번호: 'A' + 숫자 6자리 (예: A012345). 앞에 아무 말이 없어도 찾습니다.
[[patterns]]
entity = "CHART"
regex = '\bA\d{6}\b'
score = 0.95

# '접수 4821'처럼 앞말은 남기고 번호만 가리기: (?P<pii>...) 부분만 가립니다.
[[patterns]]
entity = "CHART"
regex = '접수\s*(?P<pii>\d{4,6})'

# 앞 20글자 안에 이 낱말이 있을 때만 찾기 (context)
[[patterns]]
entity = "STAFF_ID"
regex = '\b\d{5}\b'
context = ["사번", "직원번호"]

# 엑셀/CSV 열 유형: 열 제목 = 유형 (PERSON, PHONE, RRN, ADDRESS, EMAIL, MRN, BIRTHDATE ...,
#   skip = 손대지 않음, text = 자동 탐지만)
[columns]
"담당" = "PERSON"
"약품명" = "skip"

# 글자 인식 (이미지, 스캔 PDF, 문서 속 그림)
[ocr]
engine = "auto"           # auto(맥: Live Text → Vision → Tesseract) | livetext | vision | tesseract
# style = "box"           # box(검은 상자) | blur | pixelate
# pdf_images = "auto"     # PDF 속 그림: auto | true | false
# docx_images = "auto"    # 워드/한글 속 그림: auto | true | false
```

**사용자 패턴 규칙**: 정규식 전체가 가려집니다. 단 `(?P<pii>...)`라는 **이름 붙은 그룹**이 있으면 그
부분만 가립니다. 보통의 괄호 `( )`는 가릴 범위를 줄이지 않습니다. 새 항목 이름(위의 `CHART`)은 영문자·숫자·
`_`로 자유롭게 정할 수 있고, 처리 방법을 따로 정하지 않으면 통째로 가립니다(`[차트번호]`).

### [ocr] 항목

| 키 | 기본값 | 뜻 |
| --- | --- | --- |
| `engine` | `"auto"` | 글자 인식 엔진. 맥에서는 Live Text(macOS 14+) → Vision → Tesseract 순 |
| `lang` | `"kor+eng"` | Tesseract 언어 |
| `style` | `"box"` | 가리는 방식: box / blur / pixelate |
| `verify` | `1` | 가린 뒤 한 번 더 읽어 남은 것까지 가림 (0이면 끔) |
| `pdf_images` | `"auto"` | PDF 글자 쪽 안의 그림: auto(쪽의 20% 이상인 그림) / true(전부) / false |
| `pdf_dpi` | `300` | 스캔 PDF를 읽는 해상도 |
| `docx_images`, `hwpx_images` | `"auto"` | 워드·한글 속 그림: auto(충분히 큰 그림) / true(전부, OCR이 없으면 실패) / false |
| `barcodes` | `"cover"` | 바코드·QR: cover(가림) / warn(경고만) / off |
| `orientation` | `"auto"` | 옆으로·거꾸로 찍힌 사진도 돌려서 읽기 |
| `min_conf` | `30` | Tesseract 신뢰도가 이보다 낮은 글자가 많으면 경고 |
| `max_image_pixels` | `100000000` | 이보다 큰 그림은 처리하지 않음 (메모리 보호) |

### [ner], [llm]

선택 기능 설정입니다. [8장](#8-선택-기능-로컬-llm-2차-점검-ner-모델)을 보세요. 진료실 LLM 서버(`backend =
"openai"`)의 설정은 [진료실 LLM 서버 연결](#strata-등-진료실-llm-서버-연결)에 있습니다.

```toml
[llm]                      # deid check 가 쓰는 로컬 LLM (Ollama)
model = "gemma3:4b"
host = "http://127.0.0.1:11434"

[ner]                      # 신경망 이름 인식 (설치 필요)
backend = "gliner"         # gliner | hf | ollama | openai(진료실 LLM 서버)
model = "urchade/gliner_multi_pii-v1"
device = "mps"             # Apple 칩 GPU
```

설정 파일에는 **API 키·비밀번호를 적을 수 없습니다.** 파일 맨 위, `[ner]`, `[llm]`에 `api_key`, `token`,
`password`, `secret`, `strata_key`, `passphrase`처럼 key·token·secret·pass·credential·auth가 들어간 이름의
항목이 있으면(그리고 `[ocr]`, `[[patterns]]`에 `api_key`·`token` 같은 이름이 있으면) deid는 멈추고 무엇을 고칠지
알려 줍니다(값은 화면에 보여 주지 않음). 키는 키체인이나 환경변수에 두고 설정에는 그 **이름**만 적습니다.
`[columns]`의 `"Password" = "OTHER"`처럼 **엑셀 열 제목**이 Password·Key인 것은 괜찮습니다.

## 8. 선택 기능: 로컬 LLM 2차 점검, NER 모델

### 로컬 LLM으로 한 번 더 점검 — `deid check`

비식별화한 결과를 이 Mac 안의 LLM(Ollama)이 다시 읽고 "아직 남은 것 같은" 개인정보를 **화면에만**
보여 줍니다 (파일로 저장하지 않음).

```sh
brew install ollama
brew services start ollama          # 또는 https://ollama.com 에서 앱을 받아 실행
ollama pull gemma3:4b               # 처음 한 번 모델 내려받기 (약 3GB)
deid check deid_out/진료기록.deid.docx
```

- 원본 파일을 주면 먼저 비식별화한 결과를 검사합니다. 파일을 있는 그대로 검사하려면 `--as-is`.
- 다른 모델: `deid check 결과.txt --llm qwen2.5:7b`
- 16GB 맥에서는 대략 **4B~8B 크기** 모델이 무난합니다. 예: `gemma3:4b`(기본값), `qwen2.5:7b`,
  한국어에 강하다고 알려진 `exaone3.5:7.8b`(비상업 이용 조건 등 라이선스 확인). 모델 이름과 성능은 계속
  바뀌니 [ollama.com/library](https://ollama.com/library)에서 확인하고, 직접 몇 개의 예시로 시험해 보세요.
- LLM도 틀립니다(놓치기도, 없는 것을 찾기도 함). **참고용**이며, 사람의 확인을 대신하지 못합니다.
- deid는 이 Mac(127.0.0.1)이 아닌 주소의 Ollama에는 연결하지 않습니다.
- Ollama 대신 진료실 LLM 서버로 점검하려면 설정에 `[llm] backend = "openai"`를 넣습니다 (아래). 그때도 서버에는
  **비식별화한 글만** 보냅니다. 원본 파일은 먼저 비식별화하고, 서버가 이 Mac이 아니면 `--as-is`는 `.deid.` 결과
  파일에만 쓸 수 있습니다. `--host 주소`로 그때그때 다른 서버 주소(`…/v1`)를 쓸 수 있습니다.

### NER 모델 (신경망 이름 인식)

규칙만으로는 문맥 없는 이름("이서준 소아과 갔다왔어")을 놓칩니다. 신경망 모델을 켜면 일부를 더 찾을 수
있지만 **느려지고, 처음 한 번 모델을 인터넷에서 내려받습니다**(이후 처리는 이 Mac 안에서). 용량이 큽니다
(torch 포함 수 GB).

```sh
pipx inject deid-kit gliner         # GLiNER (다국어 개인정보 모델)
```

설정 파일에 `[ner] backend = "gliner"`(위 예시)를 넣고 `deid doctor`로 확인합니다.
Hugging Face 모델을 직접 고르려면 `pipx inject deid-kit transformers torch` 후
`backend = "hf"`, `model = "모델 이름"`.

> 이 모델들은 **커뮤니티가 공개한 모델**입니다. deid가 품질을 보증하지 않습니다. 라이선스를 확인하고,
> 켜기 전후로 같은 예시 글을 `deid text`로 비교해 보세요.

### Strata 등 진료실 LLM 서버 연결

진료실 PC(예: `CLINIC1`, IP `192.168.0.20`)에서 돌아가는 LLM 서버를 deid에 연결할 수 있습니다. Strata처럼 **OpenAI 호환 주소**
(`http://…/v1`)를 가진 서버면 됩니다. 두 가지 쓰임새를 **따로따로** 켭니다.

| 쓰임새 | 설정 | 서버로 가는 글 | 하는 일 |
| --- | --- | --- | --- |
| **탐지 돕기** | `[ner] backend = "openai"` | **비식별화 전 원문** | 규칙이 놓치는 이름(`님`·`환자` 없이 쓴 이름, 외국인·영문 이름, 단톡 속 호칭)과 기관 이름을 LLM이 찾고, deid의 규칙과 함께 가립니다. LLM은 "본문에 적힌 글자 그대로 + 종류"만 알려 주고, 바꾸는 일은 deid가 합니다. |
| **2차 점검** | `[llm] backend = "openai"` | 비식별화한 글만 | `deid check`가 Ollama 대신 이 서버로 남은 개인정보를 찾아 화면에 보여 줍니다. |

> **탐지(`[ner]`)를 켜기 전에 꼭 읽어 주세요**
>
> - 탐지에 연결하면 **비식별화 전 원문**(이름·주민번호가 그대로 있는 진료 기록)이 이 Mac에서 진료실 PC까지
>   **병원 내부망으로** 갑니다. "이 Mac 안에서만"이 아니라 **"진료실 PC까지"**가 됩니다.
> - 서버가 https를 지원하지 않으면 **http는 암호화되지 않습니다.** 같은 네트워크의 다른 기기가 글과 API 키를 볼
>   수 있으니 **병원 내부망(유선 또는 보안 Wi-Fi)에서만** 쓰세요. 손님용·공용 Wi-Fi, 집에서는 쓰지 마세요.
> - http는 **상대가 진짜 그 PC인지도 확인하지 않습니다.** 그래서 http 서버는 `CLINIC1`, `CLINIC1.local` 같은
>   **이름 대신 IP 주소**(예: `192.168.0.20`)로만 적을 수 있습니다. 이름은 요청마다 다시 찾는데, 노트북을 집이나
>   카페에서 열면(자동 감시는 로그인하자마자 시작) 그 이름에 답하는 **아무 기기에나** 원문과 키가 갈 수 있기
>   때문입니다. PC의 IP는 Windows에서 `ipconfig`로 확인하고, 바뀌지 않도록 공유기에서 **고정(DHCP 예약)**해
>   두세요. 그래도 병원 밖 네트워크에서는 탐지를 켠 채 쓰지 마세요.
> - 그래서 **기본은 꺼져 있습니다.** 이 Mac이 아닌 서버로는 `[ner]` 안에 `allow_remote = true`를 **직접** 적었을
>   때만 보냅니다. `[llm]`에 적은 `allow_remote`는(`deid check`용) 탐지에 쓰지 않습니다 — `[ner] backend =
>   "ollama"`도 마찬가지입니다.
> - 서버가 꺼져 있거나 키가 틀리면: `on_error = "fail"`(**권장**, 기본값)은 결과를 하나도 만들지 않고 멈춥니다
>   (클립보드는 비움). `"rules_only"`는 규칙만으로 계속하고 결과에 경고를 남기지만(단축키·빠른 동작의 알림에도
>   `LLM 탐지 실패: 규칙만 적용`), LLM이 찾았을 이름이 남을 수 있습니다.
> - 켜 두면 명령마다 `! 주의: 비식별화 전 원문(…)이 이 컴퓨터 밖의 LLM 서버 192.168.0.20:8080(으)로 전송됩니다` 경고가
>   한 번 나오고, `deid serve` 화면 맨 위와 자동 감시 기록에도 남습니다. 서버 PC에 글이 기록(로그)으로 남는지도
>   확인하세요.

**① API 키를 키체인에 넣기** (한 번만)

```sh
deid key set deid-strata
```

키를 물어보면 붙여넣고 Enter를 누릅니다. 입력한 글자는 화면에 보이지 않고, 명령줄·터미널 기록에도 남지 않습니다.
`deid-strata`는 키체인 항목 이름입니다(영문 소문자·숫자와 `. _ -`로 된 짧은 이름이면 되고, ②의
`api_key_keychain`과 같아야 합니다. `deid-session`은 deid가 쓰는 이름이라 안 됩니다).
**키는 설정 파일·명령줄·메모·저장소 어디에도 적지 마세요.**

- 있는지 확인: `deid key status deid-strata` (있다/없다만 알려 주고 값은 보여 주지 않습니다)
- 지우기: `deid key delete deid-strata`
- 처음 쓸 때 macOS가 키체인 접근을 물으면 "허용"(자주 쓰면 "항상 허용")을 누르세요.
- 키에 공백, `/`, `=`, `:` 같은 글자가 있어 `deid key set`이 저장을 거절하면, 대신
  `security add-generic-password -a deid -s deid-strata -U -w`를 실행하세요. 키를 물어보니 거기에 붙여넣습니다.
- 키체인 대신 환경변수를 쓰려면: 설정에 `api_key_env = "STRATA_API_KEY"`(영문 대문자·숫자·`_`로 된 이름;
  `DEID_VAULT_PASS` 같은 deid 자신의 변수는 안 됨)를 적고, deid를 실행할 터미널에서
  `read -rs STRATA_API_KEY && export STRATA_API_KEY`를 실행한 뒤 키를 붙여넣고 Enter. (그 터미널 창에서만
  유효합니다. 자동 감시·빠른 동작·단축어는 이 값을 모르니 키체인을 쓰세요.)

**② 설정 파일** — `deid init-config`로 만든 파일이면 `[llm]`, `[ner]` 아래의 "진료실 LLM 서버" 예시 줄 앞 `#`을
지워도 됩니다. 둘 중 하나만 켜도 됩니다.

```toml
# 탐지 돕기: 비식별화 전 원문이 진료실 PC로 갑니다
[ner]
backend = "openai"                    # "strata"라고 써도 같습니다
base_url = "http://192.168.0.20:8080/v1"   # 진료실 PC의 IP 주소 (http는 CLINIC1 같은 이름은 안 됨)
api_key_keychain = "deid-strata"      # ①의 키체인 항목 이름 (키 값이 아님)
model = "strata"
effort = "none"                       # none | low | medium | high. 탐지에는 none이 가장 빠름
allow_remote = true                   # 이 Mac이 아닌 서버로 보내려면 [ner]에 직접
on_error = "fail"                     # 서버 문제면 멈춤(권장) | "rules_only" 규칙만으로 계속 + 경고

# 2차 점검(deid check): 비식별화한 글만 갑니다
[llm]
backend = "openai"
base_url = "http://192.168.0.20:8080/v1"
api_key_keychain = "deid-strata"
model = "strata"
effort = "none"
allow_remote = true
```

- `[ner]`에 `base_url`, `api_key_keychain`(또는 `api_key_env`), `model`, `effort`, `timeout`, `max_tokens`를 적지
  않으면 `[llm]`의 값을 빌려 씁니다. `allow_remote`만은 빌리지 않습니다. 키 설정은 `[ner]`이 `[llm]`과 **같은
  서버**(같은 주소·포트)를 쓸 때만 빌립니다 — 다른 서버로 `[llm]` 서버의 키를 보내지 않습니다.
- 그 밖의 항목: `timeout`(초, 기본 180), `batch_chars`(한 번에 보내는 글자 수, 기본 4000), `max_tokens`(기본 6000).
- `[ner]`의 `backend`는 하나만 고를 수 있습니다. `openai`로 바꾸면 GLiNER 같은 다른 NER 모델은 쓰지 않습니다.
- 주소에 사용자 이름·비밀번호·`?…`를 넣거나, 이 Mac이 아닌 서버인데 `allow_remote = true`가 없거나, http 서버를
  IP 주소 대신 이름으로 적으면 deid는 처리하지 않고 멈추며 무엇을 고칠지 알려 줍니다.

**③ 점검**

```sh
deid doctor
```

| 줄 | 뜻 |
| --- | --- |
| `[OK] LLM 서버 [ner] 탐지` | 주소, 모델, effort, allow_remote, on_error |
| `[OK] API 키 [ner]` | 키를 **어디서** 찾았는지(키체인 항목 이름 또는 환경변수 이름). 키 값은 보여 주지 않습니다 |
| `[OK] LLM 서버 응답` | 서버가 응답함, `/health`의 `loaded`, 서버의 모델 이름 |
| `[!!] 원문이 이 Mac 밖으로 나감`, `[!!] 암호화되지 않은 연결` | 켜 둔 동안 늘 나오는 확인용 경고 |
| `[!!] API 키 …를 찾을 수 없습니다` | `deid key set deid-strata`로 넣거나 환경변수를 설정 |
| `[!!] LLM 서버 응답 …(HTTP 401)` | 키가 틀림: `deid key set deid-strata`로 다시 넣기 |
| `[!!] LLM 서버 응답 … 연결할 수 없습니다` | PC와 Strata가 켜져 있는지, 같은 네트워크인지. PC의 IP가 바뀌지 않았는지(`ipconfig`) |

**④ 써 보기** (지어낸 예시로)

```sh
echo "어제 오정애 와서 상담함. 정애 씨 혈압 128/82" | deid text
deid check deid_out/진료기록.deid.docx
```

**알아 두면 좋은 것**

- **서버는 한 번에 한 요청만 처리합니다.** 그래서 한 문서의 짧은 글(엑셀 셀 등)은 약 4000자씩 묶어 보내고,
  파일 이름도 한 번 더 물어봅니다. 이미지·스캔 PDF는 그림마다 한 번 보냅니다. 서버를 Open WebUI 등과 같이 쓰면
  기다리는 시간이 길어질 수 있습니다(`timeout`, 기본 180초).
- LLM이 알려 준 글자가 본문에 없으면 버립니다(개수만 셈). 띄어쓰기만 다르면 본문의 표기에 맞춥니다.
- LLM도 틀립니다. 놓치기도 하고, 진료 날짜나 일반 낱말을 가리기도 합니다(과잉 가림). 결과 확인은 여전히 사람이
  합니다.
- **같은 사람의 여러 표기**: LLM이 `박서윤`, `서윤`, `박모씨`를 같은 사람이라고 알려 주면 모두 같은 `[이름1]`이
  됩니다. 그래서 `deid restore`로 되돌리면 **대표 표기(전체 이름 `박서윤`)**로 돌아옵니다. 원문이 `서윤 씨`였던
  자리도 `박서윤 씨`가 됩니다.
- **기관 이름(ORG)**: LLM은 병원·의원·약국·회사·학교 이름도 찾습니다(LLM이 종류를 기관·병원·의원·약국·회사·
  학교 중 무엇으로 적든 같습니다). 기본은 **그대로 둡니다**(결과 요약에 `기관 1(유지)`처럼 개수만). 가리려면
  설정 파일에:

  ```toml
  [actions]
  ORG = "pseudo"     # [기관1], [기관2] ... 같은 기관은 같은 가명 (한국어로 "기관" = "가명"도 됨, 따옴표 필요)
  # ORG = "redact"   # 모두 [기관]
  ```

- **진료 날짜**: 규칙이 진료 날짜로 알아본 날짜(`2026-10-15 내원`)는 LLM이 생년월일·기타로 잘못 알려 줘도 그대로
  둡니다. 같은 사람의 표기도 LLM이 대표 표기를 **이름으로 알려 준 경우에만** 묶습니다(`어머니`처럼 이름이 아닌
  낱말은 대표 표기가 되지 않음).

- **끄기**: 설정 파일의 `[ner]` `backend` 줄을 지우거나 앞에 `#`를 붙입니다. 키도 지우려면
  `deid key delete deid-strata`.

**정말 도움이 되는지 재 보기** — 저장소 폴더의 `bench/`에 deid 규칙을 맞춰 고친 적이 없는 가상 진료 문서
95개(정답 값 449개)와 채점기가 있습니다. 규칙만 쓴 기준선은 **보호율 84.9%, 이름 75.1%**입니다. 가상 데이터라
원문이 PC로 가도 괜찮습니다.

```sh
cd ~/softkorea.github.io/tools/deid                      # 저장소 폴더 (위치는 실제 경로로)
DEID_PY="$(pipx environment --value PIPX_LOCAL_VENVS)/deid-kit/bin/python"
"$DEID_PY" bench/score_values.py bench/fresh_a.jsonl bench/fresh_b.jsonl                         # 규칙만
"$DEID_PY" bench/score_values.py bench/fresh_a.jsonl bench/fresh_b.jsonl --config ~/deid-bench-strata.toml
```

`~/deid-bench-strata.toml`에는 ②의 `[ner]` 부분만 넣습니다. 두 결과를 나란히 놓고 **보호율(특히 이름)이
오르는지**, `과잉 변경`과 `keep 보존`이 나빠지지 않는지(진료 날짜를 가리는지) 봅니다. 자세한 방법과 결과 읽는
법은 [bench/README.md](bench/README.md)에 있습니다. `--verbose`는 값 자체를 화면에 보여 주므로 **가상 코퍼스에만**
쓰고, 결과를 공개 이슈에 올리지 마세요.

## 9. 한계와 주의

**자동 탐지는 완벽하지 않습니다. 공유 전에 반드시 결과를 확인하세요.** 일부러 어렵게 만든 가상 기록으로
시험했을 때(2026년 10월) 번호·주소·생년월일은 모두 찾았지만, **이름은 100개 중 8개꼴로 놓쳤습니다** (대부분
`님`·`환자` 같은 말 없이 이름만 쓴 경우). 특히 다음은 놓치거나 남을 수 있습니다.

- **문맥 없는 이름**: `님`·`씨`·`환자`·`보호자` 같은 말이나 `이름:` 같은 제목 없이 이름만 쓴 경우
  ("이서준 소아과 갔다왔어", "D: 정해솔/한다솜", 직원 근무표, 카톡 대화 속 "민준이"). 흔한 낱말(고양이,
  지하철…)과 구별할 수 없어서입니다. 자주 나오는 이름은 설정의 `names`에 넣으세요. 별명·애칭·특이한
  이름도 마찬가지입니다.
- **제목도 시·구도 없는 짧은 주소**: "합정동 123-4에 삽니다"처럼 `주소:` 같은 제목이나 시·구 없이 쓴 주소.
  (`주소: 합정동 123-4`처럼 제목이 있으면 찾습니다.)
- **웹 주소(URL) 속 번호**: 주소는 남기고 그 안의 이름·전화번호·등록번호 등은 가리지만, 뜻을 알 수 없는
  이름표 뒤의 번호(예: `?pt=00482917`)는 남을 수 있습니다. EMR 링크는 붙여넣기 전에 지우거나, 설정에
  `[actions] URL = "redact"`(통째로 가림)를 넣으세요.
- **손글씨, 흐리거나 작은 글씨, 특이한 글꼴**: 글자 인식이 못 읽으면 가리지 못합니다.
- **사진 속 얼굴, 신체 특징, 문신**: 찾지 않습니다. 직접 가리세요.
- **문서 속 작은 그림**: 기본(auto)으로는 충분히 큰 그림만 글자 인식합니다. 검사하지 않은 그림은 경고로
  알려 줍니다(`docx_images = true`, `pdf_images = true`로 전부 검사).
- **PDF 글꼴 문제**: 글자 코드가 깨진(글꼴 일부만 넣은) PDF는 글자를 제대로 읽지 못할 수 있습니다.
- **매크로(VBA)**: xlsm·docm의 매크로 코드는 검사하지 않고 그대로 둡니다(경고 표시).
- **지원하지 않는 파일**: 폴더 처리에서는 개수만, 자동 감시에서는 아무 표시 없이 남습니다
  ([지원하지 않는 형식](#지원-형식)).
- **파일 이름**: 흔한 이름 모양은 바꾸지만 드문 이름은 놓칠 수 있습니다. 결과 파일 이름도 확인하세요.
- **날짜는 기본으로 그대로 둡니다.** 진료일·입원일만으로도 사람을 특정할 수 있는 경우(희귀 질환, 작은
  지역)에는 `[actions] DATE = "generalize"`로 바꾸세요.
- **드문 문서 구조**: 엑셀의 '이름 정의' 이름·셀 스타일 이름, 워드 입력 양식의 선택 목록, PDF 내부의
  대체 텍스트 같은 곳은 처리하지 않거나 일부만 처리합니다.
- **나이·성별·진단·희귀 사건의 조합**으로도 사람을 알아볼 수 있습니다. 도구는 이런 "간접 식별"을
  판단하지 못합니다.
- 복원(`deid restore`)은 LLM 답변에 `[이름1]`이 그대로 남아 있을 때만 됩니다. LLM이 표시를 바꾸면
  (`[이름 1]`, `이름1`) 복원되지 않습니다.
- **진료실 LLM 서버로 탐지해도** 놓치는 것이 있고, 진료 날짜·일반 낱말을 가리는 과잉 가림이 생길 수 있습니다.
  같은 사람의 여러 표기를 한 가명으로 묶으면 복원할 때 대표 표기(전체 이름)로 돌아옵니다.

### 9-1. 개인정보가 남아 있으면

결과에서 이름이나 번호가 남은 것을 발견했다면, 순서대로 하세요.

**① 바로 멈추고 지우기**

- 더 공유하지 말고, 그 결과 파일(`deid_out` 안의 파일, 메일·메신저로 보낸 첨부 포함)을 지웁니다.
- 아직 아무 데도 붙여넣지 않았다면 ③으로 갑니다.

**② 이미 클라우드 LLM이나 다른 사람에게 보냈다면**

- LLM: 그 **대화(채팅)를 삭제**합니다. 그리고 그 서비스 설정에서 "대화를 모델 학습(개선)에 사용"하는 항목이
  **꺼져 있는지** 확인합니다.
- 사람(동료·학회 등): 받은 사람에게 삭제를 부탁합니다.
- 소속 기관의 **개인정보 보호책임자에게 알립니다.** 환자에게 알리거나 신고해야 하는지는 보호책임자가
  판단합니다. 혼자 판단하거나 미루지 마세요. 언제, 어디에, 어떤 항목이 나갔는지 적어 두면 도움이 됩니다.

**③ 다시 일어나지 않게**

| 놓친 것 | 이렇게 |
| --- | --- |
| 이름 | 설정 파일의 `names` 목록에 넣기 |
| 우리 병원만의 번호 형식 (차트번호, 접수번호 등) | 설정 파일의 `[[patterns]]`에 넣기 ([7장](#7-설정-파일)) |
| 엑셀의 열 하나 전체 | `deid file 명단.xlsx --column "열제목=PERSON"` 또는 설정의 `[columns]` |
| 웹 주소 속 번호 | 설정 `[actions]`에 `URL = "redact"` |

그런 다음 **원본 파일에서 다시** 처리하세요. 이미 처리한 `.deid` 결과 파일을 다시 넣지 마세요 (가명
번호가 엇갈리고, 원본에 있던 `환자명:` 같은 문맥이 사라져 오히려 더 놓칠 수 있습니다). 새 결과도 다시
확인합니다.

**④ 탐지 오류 알리기 (도구가 나아지도록)**

- **실제 진료 기록은 절대 보내지 마세요.** 일부만 잘라낸 것, 캡처, deid 결과물도 안 됩니다 (놓친 그 정보가
  들어 있으니까요).
- 대신 같은 문제가 생기는 **지어낸 예시**를 만드세요. 가상의 이름·번호로 바꿔 쓴 뒤, 같은 문제가 생기는지
  먼저 확인합니다.

  ```sh
  echo "D: 정해솔/한다솜 오전 근무" | deid text
  ```

- 그 예시와 `deid --version` 결과, 무엇이 가려져야 했는지를 적어 저장소의
  [Issues](https://github.com/softkorea/softkorea.github.io/issues)(**누구나 볼 수 있는 공개 게시판**입니다)나
  이 도구를 전해 준 사람에게 보냅니다.

## 10. 개인정보보호법 관점 메모

> 법률 자문이 아닙니다. 기관의 개인정보 보호책임자, 내부 지침, 보건의료 데이터 관련 가이드라인을 따르세요.

- **가명처리와 익명처리는 다릅니다.** 개인정보보호법에서 가명처리는 *추가 정보 없이는* 특정 개인을 알아볼
  수 없게 처리하는 것이고, 그 결과(가명정보)는 **여전히 개인정보**입니다. 익명정보는 다른 정보를 합쳐도
  더 이상 개인을 알아볼 수 없는 정보로, 법 적용 대상에서 빠집니다.
- deid의 `[이름1]`, `[등록번호1]` 같은 **가명 + 대응표(보관함)** 방식은 **가명처리**에 해당합니다. 대응표가
  법에서 말하는 "추가 정보"입니다. 따라서
  - 대응표(세션 보관함, `--vault` 파일)는 결과물과 **분리해서** 안전하게 보관하고, 함께 보내지 마세요.
  - 세션 보관함은 마지막으로 쓴 뒤 12시간이 지나면 다음 실행 때 지워지고, `deid forget`으로 바로 지울 수
    있습니다. 그 전까지는 이 Mac에 암호화되어 남아 있습니다.
  - `--vault` 파일은 암호로 잠기지만, 암호를 같은 곳에 적어 두지 마세요.
- 통째로 가림(`redact`)·넓게 바꿈(`generalize`)만 쓰고 대응표를 남기지 않아도, 날짜·진단·지역의 조합으로
  개인을 알아볼 수 있으면 익명정보라고 할 수 없습니다.
- 클라우드 LLM에 붙여넣는 것은 그 회사(대개 해외)로 정보를 보내는 일입니다. 가명처리했더라도 기관 지침과
  환자 동의 범위를 확인하세요. 가능하면 꼭 필요한 부분만 붙여넣으세요.
- 탐지에 진료실 LLM 서버를 연결하면 **원문이 그 PC로 전송되어 처리**됩니다. 같은 의원 안의 PC라도 그 서버의 기록
  (로그) 보관, 접근 권한, 같은 서버를 쓰는 다른 프로그램을 기관 지침에 맞게 관리하세요.
- 이 도구는 법적 요건 충족을 **보증하거나 인증하지 않습니다.**

## 11. 문제 해결

먼저 `deid doctor`를 실행하세요. 문제가 있으면 그 결과와 `deid --version`을 그대로 보여 주면 됩니다.

| 표시 / 증상 | 뜻과 해결 |
| --- | --- |
| `[OK]` | 정상 |
| `[--]` | 선택 기능이 없음 (없어도 기본 기능은 동작) |
| `[!!]` | 확인 필요. 아래 `->` 줄의 안내를 따르세요 (설정 파일의 작은 문제도 여기에 나옵니다) |
| `[XX]` | 꼭 고쳐야 함 (예: 글자 인식 엔진이 하나도 없음 → `brew install tesseract tesseract-lang`) |
| `deid: command not found` | `pipx ensurepath` 후 터미널을 다시 여세요 |
| Automator·단축어에서만 안 됨 | PATH 문제입니다. [macos/README.md](macos/README.md)의 `PATH=...`가 들어간 줄을 그대로 쓰세요 |
| 한글이 `???`로 깨짐 | 단축어 스크립트 앞에 `LANG=en_US.UTF-8`을 붙이세요 |
| `deid shot`이 바탕화면만 찍음 | 시스템 설정 → 개인정보 보호 및 보안 → 화면 기록(또는 "화면 및 시스템 오디오 녹음")에서 터미널/단축어 허용 |
| 키체인 접근을 묻는 창 | deid의 세션 열쇠(`deid-session`)입니다. "항상 허용"을 누르세요 |
| "키체인을 열 수 없어…" | 키체인 접근 앱에서 로그인 키체인 잠금을 풀고 다시. 계속되면 `deid forget` |
| "다른 deid 명령이 사용 중…" | 다른 deid(감시, 웹 화면)가 보관함을 쓰는 중입니다. 잠시 뒤 다시 |
| 복원이 안 됨 | 마지막 사용 후 12시간이 지났거나 `deid forget`을 실행한 경우, LLM이 `[이름1]` 표시를 바꾼 경우, 또는 `--vault`로 만든 결과인데 `--vault` 없이 복원한 경우 |
| "보관함 파일(--vault)의 암호를 물어볼 터미널 창이 없습니다" | 빠른 동작·단축어에서 `--vault`를 쓸 때: `DEID_VAULT_PASS` 환경변수가 필요합니다 ([macos/README.md](macos/README.md) 5번) |
| "보관함을 열 수 없습니다: 암호가 틀렸거나…" | 만들 때의 암호를 쓰세요. 암호를 잊었다면 그 보관함으로는 복원할 수 없습니다 |
| 이미지·스캔 PDF에서 아무것도 못 찾음 | `deid doctor`의 OCR 항목 확인 |
| HEIC 사진이 안 열림 | `deid doctor`가 알려 주는 `pipx inject deid-kit pillow-heif` 실행 |
| 포트 사용 중 (`deid serve`) | `deid serve --port 8800` |
| "설정 파일 오류 (config error)" | deid가 처리하지 않고 멈춘 것입니다 (고칠 때까지 모든 명령이 멈춤). 메시지가 무엇이 틀렸는지(몇째 줄, 비슷한 이름) 알려 줍니다. 고친 뒤 `deid doctor`. 처음부터 다시 만들려면 `deid init-config --force` |
| "같은 [actions] 표가 두 번 있습니다" | 예시를 기존 파일 아래에 붙여넣은 경우입니다. 파일 내용을 모두 지우고 붙여넣거나, 두 `[actions]` 아래 내용을 하나로 합치세요 |
| 설정을 바꿨는데 자동 감시·웹 화면에 반영이 안 됨 | 고친 설정에 오류가 있어 이전 설정으로 돌고 있을 수 있습니다. `deid doctor`와 `~/Library/Logs/deid-watch.log`를 확인하세요 |
| 업데이트했는데 그대로인 것 같음 | `deid --version` 확인. 자동 감시는 `deid install-watch` 다시 실행, `deid serve`는 다시 시작 |
| "LLM 서버(…)가 API 키를 받아들이지 않았습니다(HTTP 401)" | 키가 없거나 틀림. `deid key set deid-strata`로 다시 넣고 `deid doctor` |
| "LLM 서버(…)에 연결할 수 없습니다" | 진료실 PC와 Strata가 켜져 있는지, 같은 네트워크인지 확인. PC의 IP 주소가 바뀌었으면(`ipconfig`) base_url을 고치고 공유기에서 고정 |
| "base_url에는 서버 이름(…) 대신 IP 주소를 적으세요" | http 서버는 `CLINIC1` 같은 이름 대신 `http://192.168.0.20:8080/v1`처럼 IP로 |
| "…설정 [ner]의 API 키를 찾을 수 없습니다" | 키체인 항목이나 환경변수가 없음. `deid key status deid-strata`로 확인 |
| "…allow_remote = true를 직접 적으세요" | 이 Mac이 아닌 서버를 쓰려면 그 표(`[ner]` 또는 `[llm]`)에 `allow_remote = true`. 원문 전송을 원하지 않으면 `[ner]` backend 줄을 지우세요 |
| "…요청을 거절했습니다(HTTP 400)" | `effort` 값이 서버가 받지 않는 값이거나 한 번에 보낸 글이 너무 김. `effort = "none"`, `batch_chars`를 줄이기 |
| "LLM이 JSON 형식의 답을 만들지 못했습니다(HTTP 502 …)" | 그 문서만 실패한 것입니다. 다시 실행하거나 `max_tokens`를 늘리고 `batch_chars`를 줄이세요 |
| "LLM 서버(…)가 …초 안에 답하지 않았습니다" | 서버가 다른 작업 중. 잠시 뒤 다시, 또는 `timeout`을 늘리기 |
| `! LLM 탐지가 글 N부분 중 K부분에서 실패해 … 규칙 기반 탐지만 적용` | `on_error = "rules_only"`일 때의 경고. 그 결과에는 LLM이 찾았을 이름이 남아 있을 수 있으니 서버를 고친 뒤 다시 처리하세요 |
| 설정 파일에 `api_key`·`token` 같은 항목이 있다는 오류 | 설정 파일에는 비밀값을 적을 수 없습니다. 그 줄을 지우고 `deid key set …` + `api_key_keychain = "…"` |

## 12. 개발자용

```sh
cd tools/deid
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q                 # 전체 테스트
.venv/bin/python bench/run_bench.py           # 탐지 정확도 (bench/corpus.jsonl, 가상 인물)
.venv/bin/python bench/score_values.py bench/fresh_a.jsonl bench/fresh_b.jsonl   # held-out 값 단위 누출
```

- 구조와 모듈 간 약속: **[CONTRACT.md](CONTRACT.md)** (끝의 Amendments가 최신)
- 소스: `src/deid/` — `engine.py`(탐지기, 전파), `recognizers/`(규칙: 번호·주소·이름), `anonymizer.py`,
  `vault.py`(가명 대응표), `formats/`(파일 형식별 처리), `ocr.py`, `cli.py`, `web.py`, `watch.py`, `mac.py`,
  `session.py`, `backends/`(선택: NER, Ollama, OpenAI 호환 LLM 서버 `openai_compat.py`)
- Python API:

  ```python
  from deid import deidentify, Detector, Anonymizer, Vault
  text, report = deidentify("환자명: 홍길동, 연락처 010-1234-5678")
  ```
